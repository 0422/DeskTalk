
本文档描述 Desk-talk 的系统架构、技术栈选择、目录结构和关键设计决策。

## 1. 系统架构

### 1.1 整体数据流

```
┌─────────────────────────────────────────────────────────────┐
│                        Desk-talk 机器人                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  麦克风 (INMP441)                                            │
│     ↓ I2S 数字音频                                           │
│  ┌─────────────┐                                            │
│  │ ESP32-S3    │                                            │
│  │ ┌─────────┐ │  唤醒词检测  ──→ WakeNet9 / MultiNet7        │
│  │ │ Audio   │ │  云端 ASR   ──→ 火山引擎 WebSocket          │
│  │ │ Pipeline│ │  LLM 生成   ──→ DeepSeek SSE (HTTPS)       │
│  │ └────┬────┘ │  TTS 合成   ──→ 火山引擎 V3 WebSocket       │
│  │      ↓      │  表情显示   ──→ SSD1306 OLED (I2C)         │
│  │   VAD 音频   │  状态灯     ──→ WS2812 (GPIO48)            │
│  │      ↓      │  舵机控制   ──→ PWM GPIO12/13               │
│  │   云端链路   │                                            │
│  └──────┬──────┘                                            │
│         ↓                                                    │
│  功放 (MAX98357)                                              │
│         ↓                                                    │
│  喇叭播放                                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 云端链路时序

```
用户说话结束
    ↓
VAD 判定静默（500ms）
    ↓
ASR WebSocket 上传音频 → 云端识别文本（~250ms）
    ↓
DeepSeek SSE 流式接收 → 分句识别（~850ms 首字节）
    ↓
TTS WebSocket 发送文本 → 首 PCM 到达（~490ms）
    ↓
I2S DMA 提交播放（~1ms）
    ↓
扬声器出声

说完后到首音频典型延迟：2.4–2.6 秒
```

## 2. 技术栈

### 2.1 硬件

| 器件 | 规格 | 用途 |
|------|------|------|
| ESP32-S3-N16R8 | Xtensa LX7 双核 240MHz, 16 MB Flash, 8 MB PSRAM | 主控 |
| INMP441 | I2S 数字麦, 24-bit, 8 kHz–48 kHz | 音频采集 |
| MAX98357-BGA | I2S D 类功放, 8Ω 2W | 音频播放 |

| 层级 | 技术/组件 | 说明 |
|------|---------|------|
| 框架 | ESP-IDF v5.3.x | 原生 FreeRTOS 任务、事件循环、组件管理 |
| 音频采集 | ESP-IDF I2S Driver | INMP441 16 kHz 单声道 PCM |
| 本地唤醒 | ESP-SR 2.5.4 | AFE + WakeNet9 + MultiNet7 |
| 云端 ASR | esp_websocket_client 1.8.0 | 火山引擎二进制协议 |
| LLM | esp_http_client | DeepSeek Chat Completions (SSE) |

## 4. 关键设计决策

### 4.1 板端直连 vs 网关

当前采用 **ESP32-S3 直连三条云端链路**（ASR / LLM / TTS），原因：
- 避免网关部署复杂度和网络依赖
- ESP32-S3 内存虽紧，但顺序执行三条 TLS 可行
- 实测延迟约 2.4–2.6 秒，满足非实时场景需求

**已知瓶颈**：TTS WebSocket 每轮新建，约 0.6–0.8 秒建连开销。
**可选方案**：流式网关（仅 V1 工程有实现，V2 未移植），实测延迟劣于直连，暂不启用。

### 4.2 ESP-IDF vs Arduino

V1 使用 Arduino 框架，V2 迁移至 ESP-IDF，原因：
- ESP-SR / ESP-ADF 官方组件仅提供 ESP-IDF 版本
- FreeRTOS 任务优先级控制（TTS 播放任务 vs 网络任务）
- PSRAM 和 mbedTLS 内存精细配置
- I2S DMA + 音频流水线稳定性

### 4.3 TTS 连接复用

火山引擎 V3 双向接口支持 Session 复用，但当前**未启用常驻连接**，原因：
- ESP32-S3 内部 RAM 约 512 KB，单条 TLS 握手约需 45 KB
- TTS 常驻后剩余内部 RAM 不足以下一轮 ASR/LLM 握手
- 当前策略：唤醒后建立 TTS，对话期间复用，ASR 前主动释放

### 4.4 双麦设计

当前仅使用 INMP441 左声道，原因：
- ASR 云端接口要求单声道 16 kHz PCM
- 双麦下混（(L+R)/2）未实现，若改为立体声采集还需额外混合步骤
- 单麦已验证可用，待后续优化拾音距离

## 5. 内存与性能

### 5.1 RAM 分布

| 区域 | 容量 | 用途 |
|------|------|------|
| 内部 SRAM | 512 KB | Wi-Fi 栈、FreeRTOS、TLS 上下文、任务栈 |
| Octal PSRAM | 8 MB | PCM 队列、音频缓冲、大对象 |

### 5.2 TLS 内存开销

| 连接 | 约占用内部 RAM |
|------|-------------|
| ASR WebSocket | ~45 KB |
| DeepSeek HTTPS | ~45 KB |
| TTS WebSocket | ~45 KB |

**限制**：三连接不能同时常驻，当前顺序执行。

### 5.3 延迟基线

| 阶段 | 典型耗时 | 说明 |
|------|---------|------|
| VAD 静默等待 | 500 ms（配置阈值；实测停讲话端点等待均值约 790 ms） | 句尾判定 |
| ASR 最终文本 | ~250 ms | 云端识别 |
| DeepSeek 首字节 | ~850 ms | 含 TLS 握手 |
| TTS 首 PCM | ~490 ms | 含 TLS 建连 |
| I2S 提交播放 | ~1 ms | 本地 DMA |
| **说完后首音频** | **2.4–2.6 秒** | 中位数 |

详见 [版本历史](版本历史.md) 各版本的延迟优化记录。

## 6. 待开发计划

- 多 LLM / 多唤醒词配置化
