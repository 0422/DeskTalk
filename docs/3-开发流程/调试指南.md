# 调试与诊断指南

本文档汇总 Desk-talk 固件调试过程中常用的日志关键词、诊断方法和常见问题排查步骤。

## 串口监视器

### 启动监视器

```bash
idf.py -p COM4 monitor
```

常用快捷键：
- `Ctrl+]`：退出监视器
- `Ctrl+T`、`Ctrl+L`：开启/停止日志文件保存

### 日志级别

建议开启的诊断日志：
- ✅ `LAT`：延迟轨迹（VAD → 首音频各阶段时间戳）
- ✅ `MEM`：ASR/LLM/TTS 内存快照
- ✅ `STACK`：FreeRTOS 任务栈高水位
- ✅ `zero PCM`、`partial PCM`：TTS 截断告警
- ⚠️ `MEM ASR/LLM/TTS`：高频内存日志（调试时开启，正式版关闭）

## 延迟诊断

### 关键日志行

```
LAT VAD_END -> ASR_FINAL: 225 ms
LAT ASR_FINAL -> LLM_DONE: 1125 ms
LAT LLM_DONE -> PLAYBACK_START: 1098 ms
LAT total: 2448 ms
```

### 延迟拆解

各阶段典型耗时见 [架构说明.md §5.3 延迟基线](../架构说明.md#53-延迟基线)；上文"关键日志行"为一次实际采样。

### 性能优化方向

1. **LLM HTTPS 长连接**：预期节省 ~0.5 秒/轮（握手开销）
2. **TTS 连接复用**：预期节省 ~0.7 秒/轮（建连开销）
3. **VAD 阈值调整**：500ms → 650ms 可降低截断风险

## TTS 完整性诊断

### 成功标志

```
TTS segment 1 END (... PCM bytes, ... frames, completion=explicit)
queued == played
discarded == 0
```

### 异常标志

```
TTS socket closed without an explicit final frame ...
TTS PCM sequence gap ...
TTS persistent connection released before cloud request because internal heap is low
```

### 截断判断

| 场景 | PCM 时长 | 判断 |
|------|---------|------|
| 收到明确完成标志 | 任意 | ✅ 完整 |
| 无完成标志但 PCM ≥5s | ≥5s | 可能完整，缺少标志 |
| 无完成标志且 PCM <3s | <3s | ⚠️ 可疑截断 |
| 首次 0 PCM，重试成功 | 重试后 >3s | ✅ 快速重试生效 |

## 内存诊断

### 关键日志

```
MEM ASR before-connect: internal=99600, largest=45000
MEM ASR after-connect: internal=54500, largest=28000
MEM LLM: internal=86700 → 41000（约占用 45KB）
MEM TTS: internal=86100 → 40900（约占用 45KB）
```

### 内存水位解读

| 字段 | 正常范围 | 警告线 |
|------|---------|--------|
| `internal`（当前空闲） | ≥30 KB | <20 KB |
| `internal_min`（历史最低） | ≥20 KB | <10 KB |
| `largest`（最大连续块） | ≥15 KB | <8 KB |
| `psram` | ≥5 MB | <4 MB |

**TLS 占用**：单条连接约 45 KB，三连接不能同时常驻（详见 [架构说明.md §5.2](../架构说明.md#52-tls-内存开销)）。

## Wi-Fi 诊断

### 正常状态

```
I (12345) wifi:state: run -> connecting (bssid: ..., ssid: ..., ...)
I (12346) wifi:state: connecting -> connected (ssid: ..., bssid: ..., ...)
I (12347) network: got ip: 192.168.x.x
```

### 异常状态

```
E wifi: failed with WIFI_REASON_NO_AP_FOUND
W wifi: disconnect request
E network: wifi disconnected, retry in 5s
```

### 配网模式

```bash
# 启动后创建配网热点 Desk-Emoji（当前固件仍用此名）
# 浏览器访问 192.168.4.1
# 选择可用 Wi-Fi 并输入密码
```

## 常见问题排查

### 1. 唤醒词不响应

- 检查 `WakeNet: Ready` 是否打印
- 检查 WakeNet 初始化耗时（正常 <2s）
- 检查 OLED/表情初始化是否阻塞（正常 <1s）
- 检查 VAD 阈值是否过低

### 2. ASR 识别失败

- 检查 ASR WebSocket 是否连接成功
- 检查音频上传是否完整
- 检查 `ASR_FINAL` 是否收到最终文本

### 3. LLM 无响应

- 检查 DeepSeek API 密钥是否正确
- 检查 SSE 流是否正常接收
- 检查网络连接和 TLS 握手

### 4. TTS 播放截断

- 检查 `TTS segment 1 END` 是否打印
- 检查 `completion=explicit` 是否出现
- 检查 `seq_last` 和 `seq_gap` 是否连续
- 查看 `partial PCM` 或 `zero PCM` 日志

### 5. 舵机抖动

- 检查供电是否充足（5V 2A+）
- 检查是否并发写 GPIO12/13（人脸跟随 + 动作任务）
- 检查舵机中心位校准

### 6. 串口通信失败（V1）

- 关闭 Arduino IDE 串口监视器
- 检查 COM 口是否被占用
- 重新插拔 USB 并刷新端口
