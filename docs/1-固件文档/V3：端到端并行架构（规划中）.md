
> 本文档为 V3 阶段总体规划；句子级分段、TTS 物理连接复用和部分并行调度已在 V2 中落地验证。

## 设计目标

从 V2 的"级联式"（ASR → LLM → TTS 顺序等待）改为**端到端并行流水线**，目标将说完后首音频延迟稳定压至 **2 秒以内**。

## 核心变更

### 1. LLM 流式触发 TTS

当前 V2 实现：
```
DeepSeek SSE 接收 → 切出完整句子 → 句子入 TTS 队列 → 播放
```

V3 目标：
```
DeepSeek SSE 接收 → 识别首个完整句子 → 立即触发 TTS → 同时 LLM 继续生成后续内容
```

### 2. Session 级连接复用

- 同一回答内多分句复用同一 TTS WebSocket
- LLM 生成与 TTS 合成并行执行
- 下一句可在上一句播放期间合成

### 3. 完整 JSON 后置

- 动作解析和历史保存仍等完整 JSON
- 但语音播放不再被 JSON 完整性阻塞

## 当前验证结果与预期效果

- V2 正常追问轮次（`session=23~29、31`）说完后首音频平均约 **2.500 秒**，尚未稳定达到 **<2 秒**
- TTS 首轮建连约 0.6–0.7 秒；追问轮次已复用物理 WebSocket，连接标记通常约 0.06–0.13 秒
- LLM 首字节仍约 0.53–1.34 秒，LLM HTTPS 长连接尚未实现

## 已知风险

- ESP32-S3 内存不足以同时常驻 ASR/LLM/TTS 三条 TLS
- TTS 物理连接已复用，但低内存、ASR 空结果或异常时会释放并串行重试
- 长回答（>10s TTS）完整性需验证
