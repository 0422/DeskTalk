## 设计目标

从 V2 的"级联式"（ASR → LLM → TTS 顺序等待）改为**端到端并行流水线**，目标将说完后首音频延迟稳定压至 **2 秒以内**。

## 核心变更

### 1. LLM 流式触发 TTS

当前 V2 实现：
```
DeepSeek SSE 接收 → 等待完整 JSON → 触发 TTS → 播放
```

V3 目标：
```
DeepSeek SSE 接收 → 识别首个完整句子 → 立即触发 TTS → 同时 LLM 继续生成后续内容
```

### 2. Session 级连接复用

- 同一回答内多分句复用同一 TTS WebSocket
- LLM 生成与 TTS 合成并行执行
- 下一句可在上一句播放期间合成

### 3. 完整 JSON 后置

- 动作解析和历史保存仍等完整 JSON
- 但语音播放不再被 JSON 完整性阻塞

## 预期效果

- 说完后首音频：目标 **<2 秒**
- TTS 建连开销：~0.6–0.8 秒/轮（常驻连接待评估）
- LLM 首字节 + TTS 首包并行，可节省约 0.5–1 秒

## 已知风险

- ESP32-S3 内存不足以同时常驻 ASR/LLM/TTS 三条 TLS
- TTS 每轮重建开销仍存在，连接复用未真正生效
- 长回答（>10s TTS）完整性需验证
