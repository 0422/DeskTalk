## [V3] 端到端并行架构（规划中）

**状态**：🔄 规划中  
**框架**：ESP-IDF v5.3

### 核心变更

从 V2 的"级联式"（ASR → LLM → TTS 顺序等待）改为"端到端"并行流水线：

- **LLM 流式输出后立即触发 TTS**：首个完整自然句出现后不等 JSON 完成，直接送入 TTS
- **Session 级连接复用**：同一回答内多分句复用同一 TTS WebSocket
- **LLM 与 TTS 并行合成**：DeepSeek 生成期间，TTS 同步合成前文已识别句子
- **完整 JSON 后置**：动作解析和历史保存仍等完整 JSON，但不再阻塞语音播放

### 性能预期

- 说完后首音频：目标稳定 **2 秒以内**
- TTS 建连开销：约 0.6–0.8 秒（每轮仍新建连接，常驻连接因内存限制未启用）
- 主要剩余瓶颈：LLM TLS 建连 + TTS 建连

### 已知限制

- ESP32-S3 内部 RAM 不足以同时常驻 ASR/LLM/TTS 三条 TLS
- TTS 每轮重建，连接复用未真正生效
- 摄像头和手势传感器保持禁用

### 待验证

- [ ] VAD 500ms 静默阈值是否造成句尾截断
- [ ] 长回答（>10 秒 TTS）的完整性
- [ ] 网络抖动时的降级行为

## [V2] ESP-IDF 框架迁移与功能实现

**日期**：2026-09  
**代码库**：[V2/desk_talk_idf](../V2/desk_talk_idf/)  
**框架**：ESP-IDF v5.3.5（从 Arduino 迁移）

### 架构变更

- **工程结构**：从 Arduino sketch 改为 CMake + 组件化
- **音频驱动**：Arduino `audio.cpp` → ESP-IDF I2S DMA 驱动
- **唤醒词**：Arduino ESP-SR 简化封装 → ESP-SR 2.5.4 原生组件（AFE + WakeNet9 + MultiNet7）
- **网络栈**：`WebSockets` 库 → `esp_websocket_client` / `esp_http_client`
- **云服务**：火山引擎 ASR/TTS（V3 双向接口）+ DeepSeek LLM（SSE 流式）

### 关键功能

| 功能 | 实现状态 |
|------|---------|
| 本地唤醒（Hi ESP / Hi Della） | ✅ |
| 云端 ASR（火山引擎） | ✅ |

| TTS 双向 Session + 播放队列 | ✅ |
| 多轮对话上下文（最近 2 轮） | ✅ |

### 延迟优化与测试

以下为业务级摘要，详细数据、日志与测试过程见 [1-固件文档/V2代码说明.md](1-固件文档/V2代码说明.md)：

- **VAD 句尾等待**：900ms → 650ms → 500ms
- **延迟打点**：9 个阶段统一时间戳
- **DeepSeek 流式**：SSE 增量接收，上下文压缩到最近 2 轮
- **TTS 播放队列**：独立 FreeRTOS 任务 + 有界 PCM 队列
- **8 轮连续对话测试**：成功率 8/8，平均 2.647 秒
- **20 轮延迟统计**：平均 2.596 秒（排除异常后 2.448 秒），正常样本 2.106–2.665 秒
- **TTS 连接复用**：逻辑已实现，受内部 RAM 约束（空闲堆 55 KiB < 96 KiB 阈值）未真正启用
- **网关方案**：仅 V1 工程有实现，实测 LLM 首字节约 11 秒、劣于直连，V2 未移植

### 稳定性与内存（摘要）

- **缓存断言**：模型映射常驻 + 内部栈存储 Worker 解决 Flash cache 冻结
- **TLS 内存**：PSRAM 阈值调整（4096 → 1024），任务栈移入 PSRAM
- **空白回答**：DeepSeek JSON mode 偶发空回复 → 改为纯文本流 + 最多重试一次
- **TTS 截断**：火山引擎 V3 双向接口 + 明确 `SessionFinished` 完成判断
- **TLS 占用**：单条连接约 45 KB，三连接不能同时常驻
