## [V3] 端到端并行架构（规划中，部分机制已在 V2 落地）

**状态**：🔄 整体规划中；句子级分段和 TTS 物理连接复用已回移到 V2 验证
**框架**：ESP-IDF v5.3

### 核心变更

从 V2 的"级联式"（ASR → LLM → TTS 顺序等待）改为"端到端"并行流水线：

- ✅ **LLM 流式输出后立即触发 TTS**：V2 已在硬标点处切出句子并立即入队
- ✅ **Session 级连接复用**：V2 已在追问窗口内复用 TTS 物理 WebSocket
- ✅ **LLM 与 TTS 并行合成**：TTS 播放任务可在 LLM 继续生成时处理句子队列
- ⚠️ **完整 JSON 后置**：V2 已实现回答流与播放解耦，但完整动作/历史处理仍需继续验证

### 性能预期

- 说完后首音频：目标稳定 **2 秒以内**
- TTS 首轮建连开销：约 0.6–0.7 秒；追问轮次物理连接复用后约 0.06–0.13 秒
- 主要剩余瓶颈：LLM 每轮 HTTPS 建连、模型首字节和 ASR 端点等待

### 已知限制

- ESP32-S3 内部 RAM 不足以同时常驻 ASR/LLM/TTS 三条 TLS
- TTS 物理连接已在追问窗口复用，但低内存/ASR 重试时仍可能释放并重建
- LLM HTTPS 长连接尚未实现
- 摄像头和手势传感器保持禁用

### 待验证

- [x] `400ms` VAD 对照试验已完成，并因短停顿截断恢复到 `500ms`
- [ ] 完成恢复 `500ms` 后的 20 轮短停顿复测
- [ ] 长回答（>10 秒 TTS）的完整性
- [ ] 网络抖动时的降级行为

## [V2] ESP-IDF 框架迁移与功能实现

**日期**：2026-09  
**代码库**：[V2/desk_talk_idf](../V2/desk_talk_idf/)  
**框架**：ESP-IDF v5.3.5（从 Arduino 迁移）

### 架构变更

- **工程结构**：从 Arduino sketch 改为 CMake + 组件化
- **音频驱动**：Arduino `audio.cpp` → ESP-IDF I2S DMA 驱动
- **唤醒词**：Arduino ESP-SR 简化封装 → ESP-SR 2.5.4 原生组件（AFE + WakeNet9 + MultiNet7）
- **网络栈**：`WebSockets` 库 → `esp_websocket_client` / `esp_http_client`
- **云服务**：火山引擎 ASR/TTS（V3 双向接口）+ DeepSeek LLM（SSE 流式）

### 关键功能

| 功能 | 实现状态 |
|------|---------|
| 本地唤醒（Hi ESP / Hi Della） | ✅ |
| 云端 ASR（火山引擎） | ✅ |
| DeepSeek LLM 流式回复 | ✅ |
| TTS 双向 Session + 播放队列 | ✅ |
| 多轮对话上下文（最近 2 轮） | ✅ |
| OLED 表情显示 | ✅ |

### 延迟优化与测试

以下为业务级摘要，详细数据、日志与测试过程见 [1-固件文档/V2说明.md](1-固件文档/V2说明.md)：

- **VAD 句尾等待**：900ms → 650ms → 500ms
- **延迟打点**：9 个阶段统一时间戳
- **DeepSeek 流式**：SSE 增量接收，上下文压缩到最近 2 轮
- **TTS 播放队列**：独立 FreeRTOS 任务 + 有界 PCM 队列
- **8 轮连续对话测试**：成功率 8/8，平均 2.647 秒
- **20 轮延迟统计**：平均 2.596 秒（排除异常后 2.448 秒），正常样本 2.106–2.665 秒
- **TTS 连接复用**：追问窗口内物理 WebSocket 已复用；ASR 空结果或异常时释放并串行重试
- **网关方案**：仅 V1 工程有实现，实测 LLM 首字节约 11 秒、劣于直连，V2 未移植

### 2026-09-22 增量测试

- `session=22` 为首轮，包含 TTS 预热，`speech_to_i2s_est_ms=4509.915`。
- `session=23~29、31` 共 8 个正常追问轮次，平均 `speech_to_i2s_est_ms` 约 **2.500 秒**。
- `session=30` 首次 ASR 空结果，串行重试后成功；该轮标记 `asr_retries=1`，不纳入正常延迟均值。
- `session=32` 在日志截取处仍处于重试过程。
- `400 ms` 静音阈值造成多次短停顿前半句截断，已恢复 `500 ms`，需完成恢复后的 20 轮复测。

### 稳定性与内存（摘要）

- **缓存断言**：模型映射常驻 + 内部栈存储 Worker 解决 Flash cache 冻结
- **TLS 内存**：PSRAM 阈值调整（4096 → 1024），任务栈移入 PSRAM
- **空白回答**：DeepSeek JSON mode 偶发空回复 → 改为纯文本流 + 最多重试一次
- **TTS 截断**：火山引擎 V3 双向接口 + 明确 `SessionFinished` 完成判断
- **TLS 占用**：单条连接约 45 KB，三连接不能同时常驻
