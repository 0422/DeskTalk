当前唤醒词：`Hi ESP`；`Hi Della`
> 唤醒识别完全在 ESP32-S3 本地完成，但唤醒后的 ASR、LLM、TTS 仍走现有云端流程。
> 当前流程是半双工的“先听、再回答”，不需要回声消除。
> 若后续要求在机器人说话时也能用语音打断，则需要增加播放中录音、声学回声消除和新的对话状态机。
> 
> Arduino ESP32 3.0.0 自带的 WakeNet 模型固定选择 `hiesp`，不能只修改日志文字就变成自定义唤醒词。改为使用 ESP-SR 自带的英文 MultiNet 命令检测，并把默认的 Hi ESP短语和新增的唤醒词短语注册为同一个命令。
> MultiNet 自定义命令不是专门训练的 WakeNet 模型，短语识别效果和抗误唤醒能力可能与 ESP-SR 固定 的WakeNet 模型 不同。
> 
> 唤醒后，主程序会暂停本地 MultiNet，避免它和云端 ASR 同时读取同一个 I2S 麦克风；云端 ASR 结束后再恢复 MultiNet。恢复时会清空待处理事件，并加入短暂冷却时间，避免上一段语音残留导致重复唤醒。

# Arduino 使用
Arduino IDE 默认不支持 ESP32，需要手动添加（**文件 → 首选项（Preferences）**，在 **附加开发板管理器网址** 里粘贴）：`https://espressif.github.io/arduino-esp32/package_esp32_index.json`，然后点击 **工具 → 开发板 → 开发板管理器**，搜索 **ESP32**，找到 **esp32 by Espressif Systems** 3.0.0，点击 **安装**。

```file:修复客户端控制表情时延迟大的问题
成因分析：
客户端发送 JSON 时没有换行符：
self.ser.write(msg.encode("utf-8"))

但固件使用下面方式读取：
Serial.readStringUntil('\n');

因此 ESP32 每次都要等串口默认超时，大约 1 秒，才认为命令接收完成。之后客户端又同步等待固件执行完表情并回传确认，复杂动画还会增加额外时间。

相关位置：
- D:/github/desk-emoji-main/pc_client/pc_client_v1.2.1/connect.py:90
- connect.cpp:43
- connect.cpp:216

最直接的修复是客户端发送时追加换行：
encode_msg = (msg + "\n").encode("utf-8")
self.ser.write(encode_msg)

这样 ESP32 会立即收到完整命令，通常能直接减少约 1 秒延迟。若界面本身仍会短暂无响应，则还需要把 ser.send() 放到后台线程，因为当前按钮回调会同步等待最多 10 秒。拔掉舵机只能排除供电问题，不会消除这里的软件延迟。
```
